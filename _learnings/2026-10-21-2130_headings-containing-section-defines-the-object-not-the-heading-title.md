# A heading's containing section defines the mathematical object - the heading title alone can look like a perfect match and still be wrong

**Symptom** After four audit rounds (author sweep, 5-layer audit, independent
agent, two Codex packet reviews), a full-channel Codex semantic pass with real
repo access still found 19 suspects among 311 shipped Musoyan links, and 18 of
them verified as real. The worst cluster: 14.7.2 "Դինիի հայտանիշը" linked (both
lecturers, conf=high) to the lectures' Fourier-SERIES Dini theorems - titles
matching almost character for character.

**Cause** Section 14.7 is "Ֆուրիեի ինտեգրալ". The Fourier-INTEGRAL Dini
criterion and the Fourier-SERIES Dini criterion share a name and differ only in
their containing section; the channel has zero Fourier-integral content, so no
honest link existed. Same shape: ch. 11 is "Անիսկական ինտեգրալներ", so 11.3's
by-parts/substitution headings wanted the improper-integral theorems (which
existed in Քեռյան's A4 L16 with alternate scores of 8.4), not the
definite-integral ones an earlier audit had deliberately picked. Every earlier
reviewer judged heading TITLE vs chapter-list TITLE and matched; only reading
the heading's chapter/section context exposed the object mismatch.

**Rule** When auditing a link semantically, resolve the heading's containing
chapter AND section first (matches.json carries both) and judge the object from
that context, not from the heading text. A same-name topic in the wrong setting
(series vs integral, definite vs improper, 1-D vs multi-D where the lecturer
covers both) is a wrong link under DECISIONS #9.2.

Also disproven this round: Codex's proposed retime of 17.1.1 to the partition
chapter item. The book page (v2 source p228) shows the subsection OPENS by
defining the coordinate parallelepiped, so the existing landing at that
definition is the true block start. When two reviewers disagree on a block
boundary, the scanned book page text is cheap to extract and decisive -
chapter lists alone cannot settle what the book's subsection contains.
